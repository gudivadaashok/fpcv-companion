Active Illumination, Interactively

Instead of waiting for texture, project your own light. Where a known pattern lands in the camera tells you how far away the surface is.

A projector shines stripes onto a scene and a camera, a short baseline away, watches where they land. We start with one stripe and triangulation, see why sweeping stripes one at a time is slow, then use binary and Gray code patterns to label every projector column in only eight images. Follows the Active Illumination Methods lectures (structured light range finding).

00

Choose a scene

Each scene is a synthetic depth map, so the true depth is known and the recovered depth can be checked against it.

No upload here. Structured light needs a scene whose depth we know, so you cannot bring your own photo. The plane has simple, checkable depth; the ball adds a curved surface; the steps add depth jumps and occlusion shadows. The dark patch (albedo 0.04) reflects almost none of the pattern, which makes decoding fail there.

01

Triangulation

A ray from the projector and a ray from the camera meet at the surface. The two angles and the baseline fix the depth.

Assumed geometry

A rectified pair: the camera is at x = 0 and the projector at x = b, both looking along +z, with the same focal length f = 256 px. A point (x, z) lands at camera column c = f x/z and at projector column p = f (x − b)/z. Their difference is the disparity d = c − p = f b/z, so z = f b/d. In terms of the angles α (at the camera) and β (at the projector) measured from the baseline: z = b / (cot α + cot β).

02

One light stripe

A single stripe gives one depth profile per image. The stripe bends sideways by exactly the disparity at each row.

03

Sweeping is slow

To measure every column you need a separate image for every stripe: N columns, N images.

04

Binary code patterns

Give every projector column a number. Project the bits of that number one image at a time, and each camera pixel reads its own column off as a bit string. Only log2 N images are needed.

Noise and blur are off here, so the decoded column should equal the true projector column on every pixel that was lit. With n < 8 patterns you only learn which block of 28−n columns a pixel belongs to.

05

Gray code

In plain binary, going from column 7 (0111) to 8 (1000) flips four bits at once. A Gray code changes only one bit between neighbours, so a wrong guess at a stripe edge can only move the answer by about one column.

Uses the number of patterns chosen in stage 04. Noise adds grey-level jitter to every image. Blur defocuses the projector, which smears thin stripes; the finest binary stripe is one column wide, so it vanishes first.

Why binary is worse: where several bits flip together, one misread bit can move the answer by up to 2n−1 columns. A Gray code has exactly one bit that differs between neighbouring columns, so there is only one place to go wrong at a stripe edge. (Reading Gray back uses a running XOR: b0 = g0, bk = bk−1 ⊕ gk.)

06

Decode to depth

The decoded column is the projector ray. Intersect it with the camera ray (stage 01) to get depth at every pixel.

NearFarInvalid: in shadow, outside the projector, or too dark to decode

Baseline: resolution against shadow

A one-column error in the decoded position changes the depth by Δz ≈ z2 / (f b). A larger baseline therefore gives finer depth, but it also tilts the projector's view further from the camera's, so more of the scene is hidden from one of them. Drag the baseline up and watch the depth resolution number fall while the shadow percentage grows, especially on the Steps scene.

Time of flight is a different kind of active illumination: instead of triangulating, it sends out light and measures how long the pulse (or the phase of a modulated beam) takes to return, then converts that delay to distance with the speed of light. It needs no baseline, so it has no shadows from the projector, but it needs very fast timing electronics.
