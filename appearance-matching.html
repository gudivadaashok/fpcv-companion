Appearance Matching, Interactively

Recognize an object and its pose by comparing whole images. Squeeze every image into a few numbers with PCA, and a rotating object traces a closed curve in that small space. A new image lands near the curve of the right object, at the right place on it.

Everything is computed in your browser: the objects are rendered by a small ray marcher, and the eigenvectors come from a Jacobi eigen solver written for this page. Follows the Appearance Matching lecture (the parametric eigenspace of Murase and Nayar).

00

Four objects, 48 poses each

Each object turns about its vertical axis in 7.5° steps. Every image is 48×48 grayscale, so it is one point in a 2304-dimensional space. Pick an object, then click a frame to select it.

Rendering and computing the eigenspace…

What the data looks like

Stack the pixels of an image into one long vector \(\mathbf{x}\) with 2304 entries. The training set has 4 objects × 48 poses = 192 such vectors. The object is lit from a fixed direction, so shading changes as it turns, and so does its silhouette.

The scene is simple: a plain background, no cast shadows, and one fixed camera. Real appearance matching needs the same lighting and a segmented object, or extra training images that cover other lights.

01

Eigenimages

Subtract the mean image m from every image. The eigenvectors of the covariance matrix with the largest eigenvalues are the directions of greatest variation. Shown as images, they are the eigenimages. Click the plot to set how many components to keep.

The Gram matrix trick

\[ \mathbf{X} = [\mathbf{x}_1-\mathbf{m},\ \dots,\ \mathbf{x}_N-\mathbf{m}]\ \ (2304\times 192),\qquad \mathbf{C} = \tfrac{1}{N}\mathbf{X}\mathbf{X}^{T}\ \ (2304\times 2304,\ \text{too big}) \]
\[ \mathbf{G} = \mathbf{X}^{T}\mathbf{X}\ \ (192\times 192):\quad \mathbf{G}\mathbf{v} = \lambda\mathbf{v} \;\Rightarrow\; \mathbf{C}(\mathbf{X}\mathbf{v}) = \tfrac{\lambda}{N}(\mathbf{X}\mathbf{v}) \;\Rightarrow\; \mathbf{e} = \frac{\mathbf{X}\mathbf{v}}{\sqrt{\lambda}} \]

Solving the small 192×192 problem gives the same nonzero eigenvalues. The eigen solver here is a cyclic Jacobi method: it applies plane rotations until the matrix is diagonal.

02

Reconstruct from k components

Each image becomes \(k\) coefficients \(g_i = \mathbf{e}_i\cdot(\mathbf{x}-\mathbf{m})\). Adding up the first \(k\) eigenimages, weighted by the coefficients, rebuilds an approximation. Drag the slider and watch the error shrink.

03

The pose manifold

Plot the first three coefficients \((g_1, g_2, g_3)\) of every image. As an object turns through 360°, its point travels around a closed curve. Drag to rotate the view. Click any point to see its image.

Only three of the 24 stored coordinates are drawn. Curves that look close in this view may be far apart in the other coordinates. Recognition below uses all the components you choose.

04

Recognize a new pose

The test image is rendered at an angle that is not in the training set, then optionally corrupted. It is projected into the eigenspace, and the closest point on any object's curve gives the answer. The 3D view above shows the test point as a white diamond.

How the match is made

\[ \mathbf{g} = \mathbf{E}_k^{T}(\mathbf{x}-\mathbf{m}),\qquad d(j) = \lVert \mathbf{g}-\mathbf{g}_j\rVert\ \ \text{over all stored points } j \]

The curve between neighboring stored poses is treated as a straight segment, and \(\mathbf{g}\) is projected onto each segment. That gives a pose estimate finer than the 7.5° spacing. Heavy noise barely matters, because noise spreads over all 2304 dimensions and only a few land in the first components. Occlusion is harder: it changes the image in a structured way that moves \(\mathbf{g}\) toward the wrong place.
