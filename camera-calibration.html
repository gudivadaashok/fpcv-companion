Camera Calibration, Interactively

Photograph an object whose 3D points you know. From where those points land in the image, solve for the camera's projection matrix, then split it into focal length, principal point, rotation and translation.

The object below is a corner of three orthogonal checkerboards, rendered in your browser, so the true camera is known and you can check every estimate. Follows the Camera Calibration lectures.

00

The calibration object and the true camera

Three checkerboard planes meet at the origin. Each plane has 6 × 6 inner corners spaced 10 units apart, so 108 points with known (X, Y, Z). Set the true camera with the sliders, then drag the 3D view to rotate it. The camera uses x right, y down, z forward, and xcam = R X + t.

Rotation uses R = Rz(γ) Ry(β) Rx(α). If you move the camera so the object leaves the image, the points still project and are still used. A real camera would not see them, so keep the object in view.

01

The measured image points

The camera projects each 3D point to a pixel. A corner detector would add some error, which the noise slider imitates with Gaussian noise. Choose how many of the 108 points to use. Click any point to inspect it in section 04.

Points are taken in an order that alternates between the three planes, so every subset covers all of them. Six points is the minimum, since each point gives two equations and P has 11 degrees of freedom.

02

Solve for P with the DLT

A pixel (u, v) and its 3D point X satisfy (u, v, 1) ∝ P (X, Y, Z, 1). Cross-multiplying removes the unknown scale and gives two linear equations in the 12 entries of P for each point.

Two rows of A per point

[ X Y Z 1 0 0 0 0 −uX −uY −uZ −u ] p = 0

[ 0 0 0 0 X Y Z 1 −vX −vY −vZ −v ] p = 0

Stack all rows into A, a 2n × 12 matrix. With noise, A p = 0 has no exact solution, so we minimize ‖A p‖ subject to ‖p‖ = 1. The answer is the eigenvector of AᵀA with the smallest eigenvalue. This page finds it with a Jacobi eigenvalue iteration written in plain JavaScript. With normalization on, the 3D points and pixels are first shifted to zero mean and scaled, which keeps the numbers well conditioned. P is then mapped back.

03

Decompose P into K, R and t

The left 3 × 3 block of P is M = K R, an upper triangular matrix times a rotation. An RQ decomposition splits them. Then t = K⁻¹ p₄. The scale and sign of P are free, so we fix the sign by det M > 0 and divide K by its bottom-right entry.

RQ by Gram–Schmidt

r₃ = m₃ / ‖m₃‖, r₂ = unit(m₂ − (m₂·r₃) r₃), r₁ = unit(m₁ − (m₁·r₃) r₃ − (m₁·r₂) r₂)

Kij = mᵢ · rⱼ for j ≥ i, t = K⁻¹ p₄

Here mᵢ is row i of M. This builds the rows of R from the bottom up, which is why the result is upper triangular. Try noise 3 with only 8 points: the rotation survives, but the focal length and the translation along the optical axis drift together.

04

Reprojection error and one point up close

Project each 3D point through the estimated P. The mean distance to the observed pixel is the reprojection error. Click a point to see its equations. The error on points used in the solve is optimistic. The error over all 108 points shows how well P generalizes.
