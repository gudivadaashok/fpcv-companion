Object Tracking, Interactively

01

Template matching

Cut a template from the first frame. In every new frame, slide it over a search window around the last position and score each offset. The best score gives the new position. Click the cost surface to read any offset.

The scores

SSD(d) = Σₓ [ I(x + d) − T(x) ]²

NCC(d) = Σₓ (I − Ī)(T − T̄) / (‖I − Ī‖ ‖T − T̄‖)

SSD is smallest at a perfect match but changes with brightness. NCC subtracts the mean and divides by the contrast, so it ignores gain and offset. This page shows the cost 1 − NCC so that low is good for both. The template never updates here, so it fails when the object's appearance changes, and it can jump to the distractor.

02

Mean shift on color histograms

The target is a color histogram q, weighted so that pixels near the box center count more. In each frame, mean shift repeatedly moves the box toward the pixels whose colors the target has the most of, until the box stops moving.

The update

ρ(y) = Σᵤ √( pᵤ(y) qᵤ ) (Bhattacharyya score)

wᵢ = √( q_b(i) / p_b(i)(y) ), y ← Σ wᵢ xᵢ / Σ wᵢ

A pixel gets a large weight when its color is common in the target and rare in the current box. The new center is the weighted mean of pixel positions. With an Epanechnikov kernel the kernel's own weighting drops out of this step. ρ is 1 for identical histograms. Because the histogram ignores layout, the red-orange distractor looks similar to the target.

03

Kalman filter, constant velocity

A detector reports the object's position with noise, and drops out when the object is hidden. The filter predicts where the object should be, then blends the prediction with the detection. The view zooms in on the current frame.

Predict and update

State x = [x, y, vₓ, v_y]ᵀ. Predict: x⁻ = F x, P⁻ = F P Fᵀ + Q

Update: K = P⁻Hᵀ (H P⁻ Hᵀ + R)⁻¹, x⁺ = x⁻ + K (z − H x⁻), P⁺ = (I − K H) P⁻

Prediction grows the uncertainty ellipse. Each detection shrinks it. Make R small and the filter trusts the detector. Make R large or Q small and it trusts its motion model. When the detector drops out, the ellipse keeps growing until the next detection. Set the assumed R far from the actual detector noise to watch the filter behave badly. The detections here come from a simulated detector (true position plus Gaussian noise), not from the image.
